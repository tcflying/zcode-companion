# ZCC 修复验收说明（2026-10-08）

## 一句话结论

配置里的地址指错了，已改对；改完之后用真实请求验证，**单次调用确实成功**。但界面（GUI）还没验，所以「完全可用」这句话现在还不能说。

## 原来是什么问题

MiniMax 的配置里，`zcc-companion` 这个服务地址写的是 `http://127.0.0.1:8790/v1`。

用同一把已配置的 key 去请求两个端口，结果是：

| 端口 | 谁在跑 | 结果 |
|---|---|---|
| 8790 | Servy 托管的 node 进程 | **401 拒绝**（提示需要有效 API key） |
| 8791 | ZCodeCompanion.exe | **200 通过**，返回 10 个可用模型 |

同一把 key，一个端口认、一个端口不认 —— 说明**问题不在 key 本身，而在于配置指向的那个服务不认识这把 key**。也就是说：**地址指错了服务**。

## 改了什么

只改了 `~/.minimax/config.yaml` 里的一行：

```
custom_provider.zcc-companion.options.baseURL
  改前：http://127.0.0.1:8790/v1
  改后：http://127.0.0.1:8791/v1
```

**没有动的东西**（逐项已核对）：apiKey、models、thinking、effortOptions、enabled、默认模型与会话绑定、所有服务进程。没重启、没停服、没装任何东西。

改写方式是原子的：先在同目录写临时文件、逐项比对了权限和 ACL 完全一致后才替换，替换完再复核一次。**整个文件其余每一个字节都没变**（改前 SHA `13a33ef1…`，改后 `1b66ad97…`）。

## 改完之后的真实测试

由主线程亲跑，一次、全新随机内容、不重发旧请求：

```

模型   ：account:bigmodel-individual-coding-plan::GLM-5.3-Flash
档位   ：low（只有一个档位）

时间   ：2026-10-08 06:10:21 → 06:10:29，实际耗时约 7.9 秒
```

结果 —— 12 项检查全部通过：

- HTTP 200，响应类型确实是流式
- 模型回复的正文**一字不差**就是让它回的那串随机码加 `42`
- 没有任何工具调用
- 正常结束（`stop`），并收到完整的结束标记，之后没有多余内容
- 没有报错、没有解析失败、没有超时

**所以：这条路现在是真的通了。**
